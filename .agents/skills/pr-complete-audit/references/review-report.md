# レビューレポートの構成

```markdown
## PR監査結果 — <repo>#<PR番号>
- 判定: READY / CHANGES_REQUIRED / INCOMPLETE
- 対象: base `<sha>` → head `<sha>`（確認日時）
- 目的 / 仕様正本: Issue #... / PR description ...
- 変更ファイル: N/N 確認（未取得・未確認の一覧）
- 影響経路: 入口→呼出元→変更箇所→依存先→出口（主要経路ごと）
- CI: 同一SHAで実行した検証名・結果 / 未実施（PR申告とは区別）
- 受入: 手動・実機・統合後のQA実績または残件

### 指摘（初回一括）
| ID | 優先度 | path:line | 発火条件と影響 | 根本原因 | 必要な修正・テスト |
|---|---|---|---|---|---|
| F-01 | P1 | ... | ... | ... | ... |

### 未検証 / 非ブロッカー
- ...

### 修正後の一括再確認条件
- ...

### マージ・Gate判断
- Merge: YES / NO / UNDETERMINED（理由）
- Gate / post-merge QA: COMPLETED / OPEN / NOT APPLICABLE（独立した判定）
```

## 重大度のガイド

- P0: 重大データ損失・機密漏洩・広範障害などで直ちに停止。
- P1: 主要受入契約違反、再現可能な機能破壊、重大な回帰・安全性違反でマージ禁止。
- P2: 修正が必要なバグ、重要な境界ケース欠落、検証可能な運用問題。
- P3: 明確な改善点だが、そのPRの受入や安全性を妨げない軽微なもの。

発見件数0件でも、未検証があれば READY にしない。原因別に指摘を統合し、同じ修正で治る派生症状を別々に投稿しない。
