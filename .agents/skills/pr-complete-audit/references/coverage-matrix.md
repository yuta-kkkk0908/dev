# Coverage Matrix — PR完全監査の探索表

**用途**：全変更ファイルを列挙した後、影響のある行だけ監査する。対象外は理由つき `N/A`、証跡不足は `NOT VERIFIED`。行数やテスト件数の大小では品質を判断しない。

| 調査軸 | 見る対象と具体的な失敗例 |
| --- | --- |
| 目的・受入契約 | Issue/詳細設計/実装が一致するか。実装されない入力・不要な仕様変更・未承認の閾値。 |
| 呼び出し元 | 呼び出し側の前提、API呼び出し順、戻り値の取り扱い、旧メソッド参照。 |
| 依存先 | 永続化、外部API、DB、Worker、Unityコンポーネント、ファイル、定数・設定。 |
| 型・データ | DTOの名称・意味・単位、JSON/CSV、enum、null、空配列、範囲外、デフォルト値、版移行。 |
| 状態遷移 | 起動→実行→完了/失敗/取消→再試行→復旧、二重実行、stale/timeout、競合・再入。 |
| 異常・境界 | 不正入力、空・最小/最大、途中切断、欠落アセット、容量超過、計算ゼロ・NaN。 |
| 永続化・互換 | 旧Save/旧DB、migration、バックフィル、rollback、重複イベント、再起動。 |
| セキュリティ | 認可漏れ、秘密情報ログ、任意パス・コマンド、依存更新、ライセンス制限。 |
| UI・ユーザー操作 | 多重クリック、画面遷移、表示反映、エラー通知、アクセシビリティ、実機スクショ。 |
| ゲーム/Unity | Scene/Prefab/ScriptableObject、ランタイムID、デッキ・Run・Save/Resume、他キャラ・ja/en。 |
| 生成パイプライン | Gate/Revision/Snapshot/Fork、素材参照、ComfyUIジョブ、Retry/Recovery、GPU待機・キャンセル、Clip入出力。 |
| 検証 | Unit、Integration、E2E、異常・回帰、静的解析、CI実行SHA、手動受入証跡。 |
| 配布・統合 | ビルド対象、deploy、依存・ライセンス、ブランチ競合、post-merge QA。 |

## ファイル単位の調査台帳（監査中の内部表）

全 changed files を次の形で管理する。出力は要約でもよいが、未確認項目を消さない。

`path | status(added/modified/deleted/renamed) | 変更の目的 | diff全件確認 | upstream | downstream | 関連テスト | 結果(VERIFIED/N/A/NOT VERIFIED)`

- `N/A` は影響が無いことを具体的に説明できる場合のみ。ロックファイル・データファイル・アセットも無条件に除外しない。
- 生成ファイルはソース・再生成手順・整合性を確認。大量バイナリは実体比較/検証手段がなければ `NOT VERIFIED`。
- PR差分の `...` 省略やAPIページ欠落、巨大patchのtruncationを黙認しない。

## 横断的な優先チェック

1. 変更した DTO/JSON/property と、その生成者・消費者・保存形式が同時に揃っているか。
2. 変更した状態遷移に旧イベント・再実行・失敗・タイムアウトから入れるか。
3. 新しいテストが「現在の実装が正しいこと」を証明するだけでなく、旧来の失敗を検出するか。
4. UI変更にAPI接続・権限・エラーパスがあるか。バックエンド変更にUIの状態反映があるか。
5. 資産が再利用される時、参照ID/承認状態/生成Snapshotが混ざらないか。
6. 変更の影響を受ける他のルート・パートナー・既存ユーザーの動作を破壊しないか。
